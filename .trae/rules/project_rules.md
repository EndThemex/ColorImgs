# Trae 项目规则

本文件为 Trae 在 **本项目 (`d:\search\web\ColorImgs`)** 中生效的项目级规则。
优先级: 项目规则 > 全局规则 > 系统默认行为。
冲突时,以上层为准;若上层未规定,按本文执行。

---

## 1. 通用开发原则

### 1.1 只做被要求的事

- **Do what has been asked; nothing more, nothing less.**
- 不主动添加未要求的功能、重构、注释、文档、类型注解、错误处理、向后兼容垫片。
- 不为"将来可能用到"提前抽象;三段相似的代码优于过早的封装。
- 修 Bug 不顺手清理周边代码;小功能不主动加可配置项。

### 1.2 文件创建与编辑

- **绝不**主动创建 `*.md` / `README.md` 等文档文件,除非用户明确要求。
- 优先编辑现有文件,而非新建。
- 修改前必须先 `Read` 该文件;未读过的代码不直接改动。
- 不要在文件中添加 emoji,除非用户明确要求。

### 1.3 工具使用边界

| 场景         | 首选工具                  | 禁止做法                                |
| ------------ | ------------------------- | --------------------------------------- |
| 读文件       | `Read`                    | `cat` / `head` / `tail` / `sed`         |
| 写/改文件    | `Write` / `SearchReplace` | `cat > file` / `echo > file` / `sed -i` |
| 按名搜文件   | `Glob`                    | `find`                                  |
| 搜代码内容   | `Grep`                    | `grep` / `rg`(作为命令)                 |
| 运行 shell   | `RunCommand`              | 在 Read/Edit/Write 适用的地方用 shell   |
| 复杂多步任务 | `Task`(子代理)            | 主上下文内堆砌长流程                    |

- 简单定向查询 (按名/按符号) → 直接用 `Glob` / `Grep`。
- 跨模块、需要上下文关联的探索 → 用 `Task` 子代理 `subagent_type=search`。
- 多个互相独立的工具调用 → 放在**同一个**响应里并行执行。

### 1.4 任务管理

- 任务 ≥ 3 个明确步骤时,使用 `TodoWrite` 拆分。
- 每完成一步**立即**标记 `completed`,不要攒到最后。
- 同一时刻最多一个 `in_progress`。

### 1.5 沟通与输出

- 始终使用**用户最新消息使用的语言**回复。
- 代码注释跟随代码文件的语言约定 (除非用户另说)。
- 简短直入主题;不重复用户原话,不写无意义过渡句。
- 给出时间估计 / 完成度预测 → **不允许**,只说"做什么"。

### 1.6 引用代码的方式

- 展示**尚未存在的代码**或示例:`markdown` 代码块,带语言标签,不加行号。
- 不写 `` `文件名` `` 这种会让链接失效的反引号包法。

### 1.7 Git 安全协议 (强制)

- 绝不修改 `git config`。
- 未经用户明确允许,**不**执行任何破坏性操作:
  `push --force` / `reset --hard` / `checkout .` / `restore .` / `clean -f` / `branch -D`。
- 未经允许**不**提交 (`git commit`)；更不主动推送。
- 暂存文件用 `git add <file>` 指定文件名,避免 `git add -A` / `.` 误纳敏感文件 (`.env`、凭据)。
- 不在 main/master 上 force push,若用户要求需明确警告。

### 1.8 失败处理

- 工具调用失败 / API 报错 → 不要盲目重试同样的动作。
- 先分析:是参数错?权限错?状态错?再换方案或用 `AskUserQuestion` 对齐。
